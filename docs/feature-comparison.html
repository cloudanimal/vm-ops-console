The landscape

Three overlapping categories aggregate scanner findings and prioritize them. Only two of the players are genuinely free and self-hostable (DefectDojo Community and SecObserve); the commercial tiers compete on connector breadth, proprietary risk scoring, and increasingly agentic AI. None of them run as a pure client-side browser application, which is where this console is deliberately different.

The six backend boundaries

Everything flagged Needs backend above crosses one of these six lines. The important point: they all collapse to the same small self-contained connector already on the roadmap. One backend, added once, unlocks all six.

BoundaryWhat forces it server-sideFeatures it unlocks
B1Live vendor API calls: browsers block the cross-origin request, and a token in page code would be exposedLive Tenable/Qualys/Rapid7/CrowdStrike/Wiz pulls; the full connector catalog
B2Scheduled work runs when no user (and no open tab) is presentContinuous ingestion, nightly enrichment, drift detection
B3Shared state across people needs a shared database and identityMulti-user, RBAC, SSO, multi-tenant, a served REST API
B4Writing back to Jira/ServiceNow and reading status needs a credential holderTwo-way ticket sync, live ticket status roll-up per campaign
B5Receiving webhooks / gating a pipeline needs a URL that is always listeningCI/CD break-the-build, inbound event ingestion
B6Sending mail or chat messages is a server action, not a page actionEmail / Slack / Teams notifications and digests
The connector is one small thing, not six. A single self-contained backend (the PocketBase-style option already scoped) holds the tokens, makes outbound calls, caches to a local database, listens for webhooks, and sends notifications. It stays on your machine or network, opt-in and local-first, so the console keeps working on its own and lights up the six boundaries only when you connect it.

Where we can still win inside the browser

Shipped since this analysis

  • Full asset inventory + criticality. Done: an asset register with per-host criticality tiers that feed the risk score.
  • Configurable risk weighting. Done: per-signal weight sliders and a transparent per-finding breakdown, the "not a black box" scoring the commercial tools sell.
  • Root-cause grouping. Done: the Remediations view groups findings by shared fix (one patch clears N findings across M assets), the Rapid7 / Dazz idea.

Shipped since this analysis

  • SARIF + CycloneDX import. Done: SARIF 2.1.0 code-scanning results and CycloneDX BOMs now import client-side into the Findings workbench.
  • License / SBOM view. Done: a Licenses & SBOM view inventories components and flags copyleft / unknown licenses, the SecObserve angle.

Still open, fully in-browser (no backend)

  • Broader parser coverage. SARIF and CycloneDX are in; SPDX and more native vendor CSV/JSON formats would further narrow the breadth gap versus DefectDojo (200+).
  • Theme presets + custom colors. User-selectable palettes and custom accent colors in Settings.

Our structural advantages

  • Zero install, zero account, zero egress. No competitor offers a genuinely local-first, open-in-a-browser experience. Data never leaves the machine.
  • Richest risk-model transparency. Showing CVSS + EPSS + KEV + LEV + SSVC + VPR side by side, and where they disagree, is more transparent than most proprietary single-score tools.
  • Cross-vendor coverage & blind spots. The Scanner Coverage view answers "which tool missed this," a framing the aggregators rarely surface directly.
  • Cost. Free and inspectable, versus quote-only enterprise pricing across the commercial field.
  • Clean upgrade path. Every dashboard already returns vendor-API-shaped data, so the connector swap is small and the local-first promise is preserved.
