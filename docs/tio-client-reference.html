Tenable.io exporter · quick reference

tio_client.py

A dependency-free command-line exporter that pulls your data out of Tenable Vulnerability Management (cloud.tenable.com) — vulnerabilities, assets, compliance, and the full config inventory.

Python 3.8+ stdlib only · no pip keys via macOS Keychain ✓ auth verified — Scan Manager, container 3726

Get started

  1. $python3 tio_client.py store-keys
    Prompts for your access + secret key (hidden input) and saves them to the macOS Keychain under service tenable-io. Create a key pair in Tenable under Settings → My Account → API Keys.
  2. $python3 tio_client.py whoami
    Validates the keys and prints your account — username, permissions, and container id. Read-only; run this first to confirm everything works.
  3. $python3 tio_client.py export-all ./tio_data --compliance-since 90d
    Dumps everything to ./tio_data as JSONL, writing a _manifest.json. Endpoints your key can't read (403/404) are skipped and recorded.

Commands

store-keyssetup Prompt for and save API keys to the Keychain.
whoamiread-only Validate keys; print account info. No data downloaded.
export-all ./tio_databulk Everything — vulns, assets, compliance, plugin & field catalogs, and all config/inventory endpoints.
vulns ./vulns.jsonlbulk Just the vulnerability export, streamed to a JSONL file.
assets ./assets.jsonlbulk Just the asset export, streamed to JSONL.
compliance ./compliance.jsonlbulk Just the compliance-findings export. Pair with --compliance-since.

Use as a library

from tio_client import TenableIO

tio = TenableIO()  # env / Keychain

# generator — memory-safe
for v in tio.export_vulns():
    process(v)

tio.export_all("./tio_data")
!
Exports are large — mind the disk. A full pull can reach tens of GB. Built-in guards:
  • export-all aborts if free disk drops below 2 GB.
  • --compliance-since 90d avoids the huge full audit history.
  • --skip drops the datasets you don't need this run.

Credential resolution: CLI flag → environment (TIO_ACCESS_KEY, TIO_SECRET_KEY) → macOS Keychain (service tenable-io).
Scope depends on the key's role — a Scan Manager key reads most datasets; admin-only endpoints (reports, audit log, roles) need an Administrator key.
Security: flag values show up in ps and shell history — prefer the Keychain or env for anything long-lived. Keys are only ever sent to cloud.tenable.com over TLS.
